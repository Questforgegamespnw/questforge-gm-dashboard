# Fake NPC System

> “They’ve always been here… haven’t they?”

## Design Goals

This system should:

- Create doubt
- Reward attentive players
- Never feel unfair
- Be easy to run

## NPC Types

### True NPCs

> “Real. Stable. Consistent.”

- Normal behavior
- Reliable memory
- Can be trusted, mostly

### Fractured NPCs

> “Still real… but slipping.”

- Minor inconsistencies
- Memory gaps
- Subtle contradictions

### Echo NPCs

> “They were never real.”

- Fully fabricated identities
- Exist to mislead, confuse, or observe
- May disappear, change, or contradict reality
- Believe they are real

## Quick Assignment Tool

When populating a scene:

- 60% True
- 30% Fractured
- 10% Echo

Keep it subtle. Too many fakes equals chaos.

## Running True NPCs

- Consistent speech
- Correctly remember past interactions
- Stable personality

## Running Fractured NPCs

Pick 1–2 quirks:

- Gets details slightly wrong
- Repeats themselves
- Pauses before answering
- Misremembers player names
- Contradicts earlier statements

Example:

Player: “You said the forge collapsed yesterday.”

NPC:

> “…Yes. Yesterday.”
>
> “…or… was it still standing?”

## Running Echo NPCs

Rule 1: They believe they are real.

Rule 2: They only break under pressure.

Baseline behavior:

- Confident
- Helpful, often
- Slightly too perfect

## Echo NPC Tells

Use 1–2 maximum per NPC.

### Subtle Tells

- Does not cast reflection
- Shadow is wrong
- Does not blink
- Knows something they should not

### Behavioral Tells

- Avoids direct answers
- Repeats phrases exactly
- Over-agrees with players

## Break Moments

Echo NPCs break when:

- Confronted
- Contradicted
- Reality shifts

Example:

NPC:

> “I’ve lived here all my life.”

Player:

> “You weren’t here yesterday.”

NPC pauses.

> “…I was.”

Then:

- Flicker
- Voice doubles
- Disappears entirely

## Hidden Trust Tracking

Each player starts with Trust = 0.

Adjust based on behavior:

| Behavior | Adjustment |
|---|---:|
| Careful observation | +1 |
| Blind trust | -1 |
| Catching inconsistencies | +2 |

### Thresholds

| Trust | Effect |
|---:|---|
| +3 | Player notices subtle tells automatically |
| +5 | Player can identify Echo NPCs with checks |
| -3 | False NPCs feel convincing; even True NPCs seem suspicious |

This creates player-driven paranoia.

## Scene Tool — The Wrong Memory

Once per session, tell a player:

> “You remember this NPC differently.”

Example:

> “You remember them having a scar. They do not now.”

Do not explain. Let them question, investigate, and spiral.

## Fake NPC Event Table — 1d8

| d8 | Event |
|---:|---|
| 1 | NPC greets player like an old friend; they have never met. |
| 2 | NPC gives correct information for the wrong situation. |
| 3 | Two NPCs contradict each other directly. |
| 4 | NPC disappears mid-conversation. |
| 5 | NPC repeats the same line hours later. |
| 6 | NPC reacts to something that did not happen. |
| 7 | NPC claims a player said something they did not. |
| 8 | NPC refers to a future event. |

## Player Tools

For fairness, give players ways to fight back.

### Insight Checks

Detect:

- Hesitation
- Inconsistencies

### Reflection Checks

Mirrors reveal truth.

### Repeated Interaction

Echo NPCs struggle with continuity.

## High-Impact Moment — The Duplicate

Use once.

Players encounter the same NPC twice at the same time.

Both:

- Claim to be real
- Act convincingly

One is Echo. One is real.

Let players decide.

## Design Philosophy

This works because it is subtle, escalates, and rewards attention.

It should not feel like random chaos or a gotcha.

## Final Result

Players will:

- Take notes differently
- Question assumptions
- Engage more deeply

Most importantly, they will feel like they solved it.
